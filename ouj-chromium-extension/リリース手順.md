# リリース手順（Chromeウェブストアへの公開）

上から順に実施する。**手を入れる場所が3か所（`投稿用.md` / `menu-whats-new.js` / `manifest.json`）
に分かれている**ので、どれか1つを忘れやすい。チェックリストとして使うこと。

---

## 1. 変更点を書く（2か所）

| 書く場所 | 何のため | 書き方 |
|---|---|---|
| [投稿用.md](投稿用.md) の `### 変更点（次回リリース予定）` | ストアの説明文のもと（git管理外の手元原稿） | 利用者向けの言葉で。1行1項目 |
| [src/menu/menu-whats-new.js](src/menu/menu-whats-new.js) の `OUJ_CHANGELOG_ENTRIES` 先頭 | 拡張機能内の「お知らせ」パネル（更新後にNEWバッジが付く） | `version: '次回リリース予定'` のブロックに要約を追記 |

「お知らせ」は画面が狭いので、投稿用.mdより短くまとめてよい。

## 2. バージョンを決めて反映する

日付ベース（例: `2026.8.1`）。次の2か所を同じ値にする。

- [src/manifest.json](src/manifest.json) の `version`
- [src/menu/menu-whats-new.js](src/menu/menu-whats-new.js) 先頭ブロックの `version: '次回リリース予定'` → `version: '2026.8.1'`

## 3. テストを通す

**実サイトへのログインは回数を絞ること**（詳細は [TESTING.md](TESTING.md) §4.1）。

```powershell
cd ouj-chromium-extension
npm run test:offline                                          # ログイン0回
npx playwright test --project=popup-desktop --project=popup-mobile   # ログイン0回
# 画面に手を入れたときだけ（ログイン1〜2回）
npx playwright test --project=desktop tests/visual/player.spec.js
```

UIを変えた場合は基準画像の焼き直し（`--update-snapshots`）と、差分が意図した変更だけかの目視確認も行う。

## 4. ストアの説明文を作る

```powershell
npm run store:release            # manifest.json の version を使う
npm run store:release -- 2026.8.1  # 明示する場合
```

これで、

1. `投稿用.md` の見出しが `### 変更点（次回リリース予定）` → `### 変更点（2026.8.1）` に変わり、
2. [ストア説明.md](ストア説明.md) が作り直される（Chromeウェブストアの「詳細な説明」にそのまま貼れるプレーンテキスト）。

コマンドの出力に**文字数（上限16,000）と概要欄（132文字）の下書き**が出るので控えておく。
`ストア説明.md` は生成物なので直接編集しない。直すのは `投稿用.md` か
[tools/build-store-description.js](tools/build-store-description.js) 側。

## 5. パッケージを作る

`src/` の中身（`manifest.json` がzipの直下に来る形）をzipにする。
**手順1〜4の変更をコミットしてから**実行すること（コミット済みの内容がそのまま入る）。

```bash
# リポジトリのルートで実行する
git archive --format=zip -o ouj-chromium-extension/src.zip "HEAD:ouj-chromium-extension/src"
```

> **⚠️ `Compress-Archive` は使わないこと**
>
> Windows PowerShell 5.1 の `Compress-Archive` も .NET の `ZipFile.CreateFromDirectory` も、
> フォルダ区切りを `\` でzipに書き込む（zipの仕様は `/`）。`menu\menu.js` のような
> エントリ名になり、拡張機能として正しく展開されない恐れがある。
> `git archive` なら `/` で書かれ、かつコミット済みのファイルだけが入る（作業中の
> ゴミファイルが混ざらない）。

できたら中身を確認する。

```bash
unzip -l ouj-chromium-extension/src.zip | head        # manifest.json が直下にあること
unzip -p ouj-chromium-extension/src.zip manifest.json | head -5   # versionが今回の値であること
```

## 6. ストアで公開する

- 作った `src.zip` をアップロード
- 「詳細な説明」に `ストア説明.md` の中身をそのまま貼る
- 「概要」に手順4で出た下書き（132文字以内）を貼る

## 7. 公開後の後始末

次回に備えて、空の「次回リリース予定」を用意してコミットする。

- `投稿用.md` … 最新の変更点の**上**に `### 変更点（次回リリース予定）` の見出しを新しく作る
- `src/menu/menu-whats-new.js` … `OUJ_CHANGELOG_ENTRIES` の先頭に
  `version: '次回リリース予定'` の空ブロックを追加（`// TODO: リリース時に…` コメントも一緒に）
- `git add` してコミット（`ストア説明.md` と `src.zip` も一緒に）

---

## つまずきやすい点

- **`npm run store:release` は手順2（manifest.jsonのバージョン更新）の後に実行する。**
  バージョンを省略すると manifest.json の値を読むため、先に実行すると前のバージョンが入る。
- `投稿用.md` は git 管理外。手元にしか無いので、環境を移すときは忘れずに持っていく
  （無い環境では `npm run store` も関連テストも動かない）。
- `ストア説明.md` と `投稿用.md` がずれていないかは `npm run store:check`
  （または `npm run test:offline`）で分かる。
- `node` が見つからないと言われたら [TESTING.md](TESTING.md) §1 を読む（PATHに出ていないだけ）。
